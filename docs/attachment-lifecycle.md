# 附件与草稿管理

附件真实位置：宿主机 `/data/apps/notes/shared/attachments/`，容器 `/data/attachments/`。笔记为共享根目录的 Markdown 文件，附件 URL 为 `attachments/<编码文件名>`，正式访问受现有 OIDC/Origin 保护。

新版网页上传携带随机 draftId。服务器按 SHA256 比较内容，相同内容返回现有 URL，不再为重复上传创建文件。不同内容沿用原文件名冲突处理。引用登记放在 `/data/apps/notes/shared/.attachment-drafts.json`，只含受管文件名、草稿引用和上传待处理文件，不含正文或身份凭据。

草稿正文在当前浏览器 localStorage 保留（兼容读取原 sessionStorage 草稿），离开/刷新/关闭标签页后可继续。保存成功释放该草稿登记，正式笔记的引用继续保护附件。删除图片并保存、删除最后引用笔记、放弃修改或删除草稿后，受管且没有其他笔记/草稿引用的附件被清理。上传回调尚未插入正文的文件暂时保留，避免另一位成员触发清理时误删。

新增 POST `api/attachment-drafts/{UUID}` 同步附件引用，body 为 content/settled/discard；现有上传新增可选 multipart draftId，笔记创建/更新新增可选 draftId。均沿用原认证和写入 Origin 检查；不更换公共认证协议。服务端单实例锁覆盖笔记写入、上传、登记与清理，JSON 原子替换；实际 Markdown 文件是引用依据，不依赖搜索索引。遇到无法读取的笔记时本次删除整体延后，服务端记录告警。

边界：历史文件或旧客户端不带 draftId 的上传不自动删除，以免破坏未知客户端正在进行的编辑。发布前盘点生产为 0 篇笔记、0 个附件，存量清理实际删除 0。仅上传新网页产生的文件纳入自动清理。若浏览器数据被用户手动清空或上传时浏览器崩溃，服务器无法据此确认草稿已被丢弃，不擅自按时间删除；应先盘点登记，再做明确的人工清理。离线/网络中断时清理请求可能延后，不能把关闭页面当作一定送达的事务。明确丢弃的失败请求会在浏览器保留待清理 ID，下次进入编辑页重试；普通同步失败后再次保存会重新同步。

回滚只切换源码 release，保留共享数据和引用登记文件；旧代码会忽略该 JSON。被明确清理的无引用文件不会因代码回滚自动恢复。当前生产存量为零，发布验证只创建并清理具名测试数据。
